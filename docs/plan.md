# Plan

## Phase 1: Bake-off (done)
Helios-Distilled was too slow for live. JoyAI-Video-Edit runs live on an RTX PRO 6000 and takes the garment as a reference image. See `pivot-joyai.md`.

## Phase 2: Live pipeline skeleton, about 1 week (can start in parallel)
- Browser webcam over WebRTC to a Python server (FastAPI + aiortc) on the GPU box, then processed frames back.
- Frontend: Next.js + TypeScript + Tailwind. Webcam page, garment picker, latency overlay (capture-to-display ms per frame).
- Start with a pass-through or dummy transform to measure transport latency on its own, then plug in the winning model.
- This part is reusable whichever model wins.

## Phase 3: Training (only if Phase 1 shows the gap), weeks to about 2 months
- Base: a streaming backbone (Causal Forcing or LongLive, around 1.3B). Fits the 96GB card for LoRA/distillation.
- Add **garment-image conditioning**.
- Distill from an offline try-on teacher (MagicTryOn) using a Self-Forcing / Causal Forcing style recipe.
- Borrow LiveVVT's design: a rolling window plus a persistent garment appearance anchor.
- Data: pairs generated by the teacher, plus public try-on datasets (VITON-HD, VVT, etc.; check licenses).
- 14B-scale training means renting H100s.

## Open questions (for the owner)
- Quality bar: upper body at 512p and about 15fps, or full body at 720p and 30fps?
- How much latency is acceptable for the product (live mirror vs about 2s delayed)?
- Commercial target: B2B retail and e-commerce, or something else? This affects license choices.
- Email the LiveVVT authors about a code release?
